# 失败重放用例（回归门禁）

生产失败必须在 24 小时内做成最小复现用例放入本目录，流程固定为三步：

1. 先确认该用例**在当前版本失败**（否则说明没复现到真正的问题）
2. 修复后确认**通过**
3. 进 CI 门禁，此后每次 playbook 变更都必跑

在自学习系统里这条是必需品——它是唯一阻止同一个错误被学进 playbook 反复犯的机制。

## 命名

`YYYY-MM-DD-<失败类型>-<简述>.json`

失败类型取三分类之一（§19.1）：`漏判` / `高估` / `不可落地`——三者归因与修正路径完全不同，必须分开统计。
