# 从 Demo 到可用工具 — 增量实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 或 executing-plans。

**Goal:** 把「只能看预置客户报告」变成「顾问可以给任意新客户建档、上传材料、跑出诊断」。

**问题定位：** 现状只实现了 S5 之后的交付物展示。S0（准入与口径）、S1（材料采集与解析）、
S2（任务级分解）三段被 `seed.py` 里写死的 `card_specs` 顶掉了，且 `api.py` 硬编码 `TENANT="minghui"`。

**Spec:** `docs/superpowers/specs/2026-08-25-ai-efficiency-agent-design.md`（§12.2 采集形态、§17 准入）

## Global Constraints

- 沿用既有冻结区：证据分级、ROI 公式、`insufficient_data` 语义、只读边界一律不改
- 新客户的场景卡必须**从上传材料推导**，不得内置任何默认场景
- 材料一律过 `guardrails.scan_attachment`：类型白名单、禁宏禁公式、注入检测
- 每个 tenant 的工作区物理隔离；检索强制带 tenant 过滤
- 推导失败时给结构化缺口，不硬造场景（`insufficient_data` 仍是一等公民）
- 预置客户 `minghui` 必须继续可用（既有 183 个测试全绿）
