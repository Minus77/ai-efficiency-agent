# 04 结论纪律

> **改代码前必读。** 每条纪律都在代码层强制，且有测试钉住。

这个项目的可信度由**代码强制**，不由提示词约定。表格里的「放宽后果」不是风格偏好——
这些是这个工具敢拿去见客户的全部理由。不了解这些强制点就改代码，最典型的后果是让工具
重新开始编数字，而测试当场变红。

## 十四条不可协商的纪律

| 纪律 | 执行位置 | 放宽后果 |
|---|---|---|
| 没有材料就没有结论 | `diagnose.run_diagnosis` 抛 `DiagnosisNotReady` → API 409 | 工具开始凭训练知识编场景，客户无法复议 |
| C 级不出现任何金额（含实施成本） | `roi.roi_estimate` 返回 `direction_only`；`guardrails.guardian_review` 在最终输出层否决 | 单方陈述被包装成可落地的钱，最典型的 ROI 幻觉 |
| 真碎片折现 0%、不进 ROI | `FROZEN["discount_rules"]`、`models.TaskCard._fragmented_is_not_quantifiable` | 把「一天摸十次、每次两分钟」算成可省工时，汇总值虚高 |
| 冲突不取均值 | `evidence.adjudicate` 按 `FROZEN["adjudication_order"]` 固定序择一，偏差 > 0.30 标 `requires_human` | 均值把两个都不对的数字变成一个看起来合理的数字 |
| 无基线不给改善率 | `measure.measure_effect` 返回 `insufficient_data` → API 422 | 只能证明「现在是多少」，却宣称是改造带来的 |
| 经营结果指标拒收 | `measure.BANNED_METRICS` + `ALLOWED_METRICS` 白名单 | 用营收波动校准场景识别会训出错误关联 |
| 连接器只读 | `guardrails.assert_readonly` + `connectors.base._WRITE_VERBS`（纵深防御两层） | 一个「顺手写回」的能力会让客户 IT 永久拒绝授权 |
| 声明等级 ≤ 实际粒度 | `ConnectorSpec.max_evidence_grade`；`test_connectors_vendor.py` 逐个校验 | IM 标成 A 级 → 下游误以为能量化 → ROI 幻觉 |
| 凭据不进响应/日志/上下文 | 明文存 `.connector-secrets.json`（gitignore 两层），`connectors.json` 不含 secret，`CredentialRef.__repr__` 屏蔽 | 凭据泄露 |
| 专家判断区不带金额且标来源 | `agents.py` 与 `tools/__init__.py` 都过 `guardrails.contains_money`；`source` ∈ `curated`/`llm`/`fallback` | 该区按设计无数据支撑，来源是读者唯一的可信度线索 |
| 熔断与配置错误必须冒泡 | `agents._NEVER_FALLBACK` / `derive._NEVER_FALLBACK` = `(CostBreakerTripped, ImportError, TypeError, AssertionError)` | 真故障看起来像「模型没话说」——最难查的一类 bug |
| 客户原始数据不进知识库 | `knowledge.KnowledgeBase` 三库物理隔离 + 去具体化检验 | 客户 A 的数据出现在客户 B 的结论里 |
| 客户间物理隔离 | `clients.safe_slug` + `guardrails.tenant_filter`；每次拉取强制带 tenant 过滤 | `../../etc` 这类路径穿越比注入更容易被忽略 |
| 无证据引用的场景卡拒写 | `models.TaskCard._must_cite_evidence` | 报告里出现无法回溯出处的结论 |

补充几条同样由测试锁死的：场景卡的频次与工时由时间戳聚簇算出，模型引用不存在的列即丢弃；
分类计数为全表精确计数（按取值分摊会让频次系统性失真）；连接器数据跨进程可复现
（种子用 blake2b 而非内置 `hash()`，后者被加盐、重启即漂移）。

## 冻结区

`config.FROZEN` 是 `MappingProxyType`，**运行时写入直接抛错**。里面是证据分级口径、
ROI 公式、`insufficient_data` 语义、只读边界、`max_steps=20`、成本熔断阈值、裁决序、
冲突阈值 0.30、折现规则。

**改这些只能改代码 + 发版**，Agent 与自学习回路一律不可触碰（架构 §9.7）。可自演进的部分
登记在 `config.EVOLVABLE_SURFACES`，仅供观测对照——其中
`rubric_weights_pending_human_approval` 的字面意思就是：七维权重变更须人工批准。

## 单一真值：三处常量与界面必须一致

| 数值 | 唯一真值 | 谁来对照 |
|---|---|---|
| 七维权重 | `feasibility.DIMENSIONS` | `glossary.difficulty_scale()` |
| ROI 三档系数（中性 1.15 / 乐观 1.35） | `roi._NEUTRAL_UPLIFT` / `_OPTIMISTIC_UPLIFT` | `glossary.tier_scale()` |
| 反评审严重度档位（高/中/低） | `agents._SEVERITIES` | `glossary.severity_scale()` |

三者都有测试断言两边一致。在任一侧硬编码第二份，等于让界面在实现改动后继续显示旧数字——
那是在骗人。

## `insufficient_data` 是 `ok=True`

`models.ToolResult.insufficient()` 返回 `ok=True`。这是架构 §6 的第一个取舍：
**「取不到数据」是正常结论，不是故障。** 所以：

- 不要用 `try/except` 把它转成异常，也不要用宽泛的 `except Exception` 包住工具调用。
  这里有一次真实事故：SOCKS 代理缺依赖导致的传输层失败，被宽泛异常伪装成
  「模型没话说」，查了很久
- `no_grounding` 是 RAG 版的同一件事：检索不到就说不知道，不许用训练知识补齐

## 证据分级与受理形态的对应

`evidence.probe_material_reachability` 是唯一入口，四种结果：

| 材料形态 | 可达等级 | 交付形态 | 受理 |
|---|---|---|---|
| 有单条记录 + 时间戳 | A | 完整诊断 | 是 |
| 有明细、无时间戳 | B | 限定诊断 | 是（须事前书面告知：耗时需补数表，ROI 仅区间） |
| 仅汇总数字 | C | 轻量咨询 | 是（不出完整 ROI，无任何金额） |
| 导不出任何结构化数据 | C | 轻量咨询 | **拒接**——真实需求是先把流程数字化 |

材料角色 `R1–R5` 见 `intake.EVIDENCE_ROLES`。编号只作为 value 传回服务端，界面上写的是人话。

## 前端也有硬约束

改前端行为（焦点、加载态、竞态、对比度）时，**静态测试与浏览器实测互相替代不了**：
静态测试能算出「合法但暂时没人写」的组合，浏览器只能量当前真实渲染出来的组合。两种都要。

- 界面上每个 `term("…")` 的键必须在术语表中存在（静态扫描，拼错即红）
- 内部实现词不得出现在界面文案里（只查会被用户读到的文案，不查 `m.xxx` 这类字段名）
- 术语分组必须覆盖全部术语且不重复——漏一个词，那个词永远不会出现在参考页
- `[hidden]` 全局强制 `display: none !important`（同一个坑踩过三次，见下）
- toast 必须是 live region；跳转链接不得用 `display:none` 隐藏（否则键盘聚焦不到）
- `.tbl-scroll` 必须有 `max-height`，否则表头 `sticky` 永远不触发
- 弹窗只能走 `openModal()`：裸 `modal.hidden = false` 不记录返回焦点，测试会数出多余的入口
- `prefers-reduced-motion` 必须以**通用选择器**全局关闭动画，不许退回逐个列举类名
- 所有可交互控件都要有 `:focus-visible`
- 窄屏媒体查询收窄的选择器必须与持有 `margin-left` 的选择器是同一个
- 文字色 token 必须在**任何**一层背景上都达到 WCAG AA（小字 4.5:1）；语义色作文字必须用
  `-fg` 变体
- 不可逆操作不得用原生 `confirm()`：必须逐条列出会被删除的内容，默认焦点在「取消」，
  三条关闭途径都要 resolve（否则 `await` 悬着）
- 换页加载态必须延迟出现（150–500ms）并标 `aria-busy`；`render()` 的成功与失败两条路径
  都要校验「当前视图是否还是我」，否则慢请求后到会覆盖用户已经切走的页面
- `autoTerm()` 必须**先转义再注入**：被替换的值只能是 `esc(text)` 的结果。这是安全属性——
  那些段落里含客户名与文件名，绑定成原始文本就等于把客户材料当 HTML 执行

## 为什么很多测试是「静态钉子」

`tests/test_web_glossary_contract.py` 有三十多条测试在扫 `web/` 的源码、比对两处常量、
计算颜色对比度。它们红了通常意味着「实现与界面/术语表说的不是一回事」，**不是测试过时**。

对比度这一项，静态测试比浏览器实测更严：浏览器只能量到当前真实渲染出来的组合，静态测试
直接算 token 两两配对，因此抓出过 `--n400` 落在 `--n75` 徽标底上只有 4.36——那是一个合法
但当时没人写的组合。

静态钉子本身也做过红-绿验证：逐个破坏行为确认对应测试真的会红。其中一条起初破坏后依然绿
（`"*" in body` 会被 `.skeleton > *` 里的星号命中），已改为匹配真正的通用选择器。

## 两个值得记下来的事故

### 同一个坑踩到第三次才去根治：`[hidden]`

元素上任何 `display` 声明都会盖掉 `hidden` 属性自带的 `display: none`，于是「隐藏」的元素
继续占位、继续吃点击。这个坑出现过三次：

1. `.modal` 的 `display: grid` 让隐形遮罩吞掉全页点击
2. 连接器搜索过滤后，空的类别分组留下一串空标题
3. 首访提示条点了「知道了」关不掉——顶栏是 `position: fixed`，压在提示条上面，
   连按钮的点击都收不到

前两次都是就地补一条 `.x[hidden] { display: none }`，属于打地鼠。第三次改成全局兜底
`[hidden] { display: none !important }`，并加测试钉住这条规则别在「整理样式」时被删掉。

### 抽样验收放过的回归：窄屏整页溢出

为了让首访提示条与内容同列，左偏移从 `.main` 移到了外层 `.mainwrap`，但 `≤1024px` 的媒体
查询仍在改 `.main`。结果窄屏下偏移一直停在侧栏全宽 216px，整页被推出视口——390px 下
14 个视图有 6 个横向溢出。

值得记下来的是**它是怎么躲过验收的**：当时全部单元测试与四套浏览器用例都是绿的，因为它们
没有任何一条在 390px 下量过页宽。响应式那句验收写的是「4 档宽度 × 4 个视图」，而溢出的那
几个视图恰好不在抽样里。

两处改法：验收从抽样改成**枚举**（5 档宽度 × 全部 14 个视图逐一量 `scrollWidth`）；
加一条静态测试断言「持有 `margin-left` 的选择器」与「媒体查询里收窄的选择器」始终是同一个。
这条测试做过红-绿验证：把 `.mainwrap` 改回 `.main` 后它确实变红。
